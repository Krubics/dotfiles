GTK theme diagnosis

Use when: a GTK CSS rule appears to do nothing.
Rule: stop at the earliest failed gate.
Review lesson 0001

1. Loaded?

  1. Identify the application’s GTK major version.
  2. Confirm which stylesheet/provider the process receives.
  3. Make one unmistakable temporary change in Inspector.
ldd "$(command -v APP)" | grep -E 'gtk|gtkmm' GTK_DEBUG=interactive gtk4-demo GTK_DEBUG=interactive waybar

Proof: Inspector lists the provider or a live edit changes the app.

2. Matched?

  1. Select the visible widget with Inspector.
  2. Record its CSS node name, #id, .classes, state, and ancestors.
  3. Compare those observations to the selector from right to left.

Proof: Inspector shows the rule on the selected node.

Remember: GTK’s CSS node tree is not a web DOM. Widget API pages document their node structures.

3. Applied?

  1. Check for unknown or removed declarations.
  2. Inspect the computed value and winning origin.
  3. Compare specificity, source order, and state.

Proof: the expected value appears in computed style.

GTK 4 warning signs: widget style properties, -gtk-gradient, -gtk-icon-effect, -gtk-icon-theme, or assumptions about GTK 3 node nesting.

Your Waybar rule, parsed

#workspaces:not(.taskbar)
  button.active
  • Find an active button.
  • It must descend from #workspaces.
  • That ancestor must not have class taskbar.

If the node tree changes, the selector can remain syntactically valid while matching nothing.
