Waybar field study / Sapphire

Battle UI, without turning the desktop into a toy.

Three interactive directions for a balanced Gen III-inspired Waybar. Each preserves the semantic Pokémon casting already in use, improves small-sprite legibility, and turns battery state into the signature Pikachu HP treatment.

01 / Current state

What already works

The real desktop capture is shown rather than reconstructed. The theme’s strongest idea is functional: each Pokémon already has a system role.

Keep: semantic casting

Dialga is time, Wooper is network, Magneton is Bluetooth, Pikachu is energy, and the Poké Ball identifies the active workspace.

Fix: information balance

The right island carries most of the detail while the center remains sparse. Labels such as “wlo1” and “1C” expose implementation details rather than useful state.

Fix: sprite scale

Wooper survives the current size. Dialga, Magneton, and the five-Pikachu strip lose defining details at roughly 26 pixels tall.

03 / Tradeoffs

What each direction optimizes

All three are feasible with Waybar’s existing module structure. The implementation cost differs mainly in how much module regrouping and custom formatting is required.

A / RECOMMENDED

Battle cards

Deepens the current three-island layout instead of replacing it. Pokémon portraits remain readable and every status keeps a textual value.

Cost: modest CSS and formatting changes. Risk: the right island still needs careful width control.
B / MOST GAME-LIKE

Encounter ribbon

Feels most like an actual Gen III battle interface. A single information hierarchy makes the HP treatment especially convincing.

Cost: substantial module regrouping. Risk: one long bar loses the airy floating-island character.
C / MOST DISTINCTIVE

PokéNav deck

Uses asymmetry and circular status portraits to make the bar feel like trainer hardware rather than a conventional desktop panel.

Cost: moderate CSS complexity. Risk: tiny badges are less readable than A’s explicit labels.
